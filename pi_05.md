# Implementing pi 0.5

The problem with our current model is that its trained to perform one single task, using one robot. It doesn't support other robots not will it work for/on a different dataset. My idea is to move to a model like pi0.5 or pi0.6 (latest one, haven't gone through it), which has a VLM backbone. This enables broader world knowlegde and context that is required to do varied types of tasks (not limited to a certain dataset). But as of today, these models are still limited to the tasks they can perform out of the box (post-trained), they all  have to be finetuned for your specific task. Which makes sense because no model can solve every single task out there, and most importantly the definition of a task differs from use case to use case. 

Although is it possible? Is it possible to create a model such that it can do basically any task its given. For eg like how LLMs handle text. Some researchers have even got LLMs to control robots, but as of today its very slow and much worse than learning policies like pi. So I thought of starting out with learning and trying out pi0.5 and then moving on to other .   

## pi-0.5

Summary of the whole model pipeline:

```
camera + words + joint readings → tokens → backbone writes subtask → backbone builds K,V notes
→ expert starts from random noise → refines it 10 times using the notes → 50 timesteps of actions
```

## Part 1: Prep the inputs

The inputs to the model. Let's assume 2048 input dim for the entirety of this example.

### Step 1: Collect sensor readings + nl instructions

- 3 camera images, each 224 * 224 pixels
- The baase instruction: eg: "clean the kitchen"
- The current joint readings (at the current timestep): eg: [0.03, 0.81]

### Step 2: Turn the images into vectors (embed)

SigLIP cuts each image into a 16x16 grid of patches (total of 256 patches). Each patch is embedded/vectorized into one vector of 2048 nums (dim_size=2048)

i.e., for 3 images - 3 * 256 = 768 image tokens (each token of 2048 dims)

### Step 3: Vectorize/Embed the instructions and joint readings

- The joint readings are rounded into 256 levels (or bins as represented in the original VLM paper) and written as text. eg: 0.03->"131", 0.81->"231"
- The task instruction is split into about 15 tokens. Each token ID is embedded (becomes a vector of 2048 numbers).

### Step 4: Line them all up

768 image tokens + 15 text tokens = 783 vectors, each 2048 long. This list is the *prefix*: everything the model knows about the current timestep.

## Part 2: The VLM backbone

The pass through the pretrained VLM (eg: PaliGemma).

### Step 5: Generate the subtask given the prefix

The VLM backbone (18 layers) reads the *prefix* and outputs (autoregressive) a probabaility for every word in its vocabulary:

```
prefix                      → "pick"   (most likely word)
prefix + "pick"             → "up"
prefix + "pick up"          → "the"
prefix + "pick up the"      → "plate"
prefix + "pick up the plate"→ <end>
```

Final generation: "pick up the plate".

### Step 6: Rebuild the prefix with the subtask and run a second pass

The text part is replaced: "Task: pick up the plate, State: 131 231; Action:". The backbone runs over this new prefix once. At each of its 18 layers, it computes two vectors for every prefix token:

- K (key): "what I am", e.g. "I'm the patch with the plate's edge"
- V (value): "what I know", meaning that patch's actual features

It saves all of these (18 layers × 783 tokens × K and V). This is the KV cache. The backbone pass is now completed.

## Part 3: The action expert

Action expert network (the action generator) and the flow matching algorithm behind it.

### Step 7: Start from pure noise

```
x = random numbers, shape 50 × 2     (50 timesteps, 2 dims)
τ = 1.0                              (meaning "this is 100% noise")
```

### Step 8: Turn each row into a token

- Each of the 50 rows (2 numbers) goes through a small linear layer and becomes a vector of 1024 numbers(just like an embedding layer). The expert is also told the current τ.
- Output: 50 action tokens (each of 1024 dims)

### Step 9: Pass the tokens through the action expert model

18 layer NN. At every layer each action token looks up:

* the backbone's saved K and V at that same layer (allowing to answer queries like: "where's the plate? is the gripper open?") - cross attention
* the other 49 action tokens (allowing to answer: "what are the neighbouring timesteps doing") - self attention

After the last layer, each token is turned back into 2 numbers.
→ v̂, shape 50 × 2: "which direction points from the clean actions toward noise"

## Pre and post Training

The VLM backbone is pretrained on tas specific prompts and multimodel web and robot data to generate context like bounding boxes and language subtasks. 

Post training includes training the VLM to generate actions (FAST tokens) and also training the action expert to generate the final robot actions given noise mixed with the actual ground truth actions (just like diffusion models that mix actual ground truth tokens with gaussian noise):

    - The *prefix* + ground truth actions (FAST tokens) is given to the VLM. 
    - Cross entropy loss on the output generations.
    - in ||el, the raw actions are masked with noise and passed through the action expert model to generate the actual final predicted actions (MSE loss with labels).
    - The action expert model computes attention with the K, V of the backbone. It can only see the K, V of the prefix tokens though and not the ones of the FAST tokens (its masked) - reason: during inference there is no FAST tokens and action values passed through the backbone.

This is one of the two types of post-training that is done in pi0.5, another part is post-trainng for planning (a set of separate inputs):
    - No FAST action tokens, the VLM backbone is given the *prefix* and it generates subtasks for the given base instruction. CE loss.
